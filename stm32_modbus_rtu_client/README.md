# STM32 Modbus Client (modbus-rs Demo)

## Overview
This project is a demonstration for developers who want to integrate the [modbus-rs](https://github.com/Raghava-Ch/modbus-rs) project into a bare-metal C environment. It implements a Modbus RTU Client (Master) on an STM32 microcontroller. The client leverages your robust, safe Rust-based `modbus-rs` stack (integrated via C-bindings generated by `cbindgen`) to handle Modbus frames and transactions natively in C.

The application is designed around a non-blocking super-loop architecture and features interrupt-driven UART communication, a ring buffer for receiving data, and non-blocking transmissions. It provides a practical example of driving Modbus state machines to poll a remote Modbus server.

## Modbus Polling Sequence & Application State
This demo repeatedly cycles through a sequence of Modbus requests directed at a Modbus server (Unit ID `1`). The state machine is implemented in `Modbus_Poll()`.

### Request Cycle
Every 1000ms, if there are no pending requests, the client initiates the next request in the cycle:

1. **Write Multiple Coils (State 0)**
   - **Action:** Writes a bit pattern (`0x0D` or `0000 1101` in binary) to 8 coils starting at address `0`.
   - **Purpose:** Used to turn on/off remote LEDs or digital outputs.

2. **Read Coils (State 1)**
   - **Action:** Reads the status of 4 coils starting at address `0`.
   - **Purpose:** Verifies the state of remote LEDs or reads remote digital inputs.

3. **Write Multiple Registers (State 2)**
   - **Action:** Writes three 16-bit values (`0x1234`, `0x5678`, `0x9ABC`) to 3 holding registers starting at address `0`.
   - **Purpose:** Sets numerical values or configurations on the remote server.

## Features
* **Modbus RTU Protocol**: Serial Modbus client connecting to unit ID `1`.
* **Rust-powered Stack (`modbus-rs`)**: Core Modbus logic is handled by a safe Rust library, interfaced via `modbus_rs.h`.
* **Non-Blocking Serial I/O**:
  * **RX**: Interrupt-driven byte-by-byte reception (`HAL_UART_RxCpltCallback`) feeding into a volatile lock-free ring buffer.
  * **TX**: Non-blocking transmission using `HAL_UART_Transmit`, with application-level timing checks.
  * **Error Recovery**: Automatic recovery from UART Overrun Errors (ORE) via `HAL_UART_ErrorCallback`.
* **Application Callbacks**: Handles response callbacks for reads, writes, and failures.

## Hardware Configuration
* **Microcontroller**: STM32H7 Series
* **UART Peripheral**: `USART3`
* **Baud Rate**: 115200 bps
* **Data Bits**: 8
* **Parity**: None
* **Stop Bits**: 1
* **Pins**: 
  * `PD8` -> USART3_TX
  * `PD9` -> USART3_RX

## Concurrency & Thread Safety
Currently, the application runs entirely in a bare-metal, single-threaded context. The Modbus client execution is driven by polling `mbus_serial_poll()` in the main `while(1)` loop. 

Stub locks (`mbus_client_lock`, `mbus_pool_lock`, etc.) are provided in `modbus.c`. If an RTOS (e.g., FreeRTOS) is integrated in the future, these stubs should be populated with Mutexes to prevent race conditions during state mutations.
